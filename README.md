# Pアプリカ (Paprica)

ウェブサイトを、本物の Android アプリ (APK) に変換するジェネレーターアプリ「アプリカ」の
**プッシュ対応版**です。通常版の WebView エンジンでは使えない、サイトの **Web プッシュ通知** を
生成したアプリで受け取れます。

> **リポジトリ移行のお知らせ**
> Pアプリカは以前、通常版アプリカのリポジトリ
> （[yorukaze-luru/aprica](https://github.com/yorukaze-luru/aprica)）で
> `push-vX.Y.Z` として公開していましたが、専用リポジトリ（このリポジトリ）に移行しました。
> **移行に伴い、バージョンは 1.0.0 から数え直しています。**
> 旧リポジトリでの最終版は push-v2.0.0 で、本リポジトリの v1.0.0 はその後継です
> （パッケージ名と署名キーは同じため、そのまま上書き更新できます）。
> 通常版アプリカは引き続き [yorukaze-luru/aprica](https://github.com/yorukaze-luru/aprica) で
> 公開しています。

## ダウンロード

[Releases](https://github.com/yorukaze-luru/paprica/releases) から `paprica-vX.Y.Z.apk` を
ダウンロードしてインストールしてください。

- パッケージ名: `app.webgen.generator.push`
- 対応: Android 8.0（API 26）以上
- 初回は Android の設定で「不明なアプリのインストール」の許可が必要です
- Google Play での配布はしていません
- 通常版「アプリカ」（`app.webgen.generator`）と同時にインストールできます（同居可能）

## 使い方

1. Pアプリカを開く
2. アプリ化したいサイトの URL とアプリ名を入力（パッケージ名は自動で提案されます。末尾に `.push` が付きます）
3. アイコンを選ぶ（サイトのアイコンを自動取得 / 画像から選択 / 頭文字アイコンの自動生成）
4. 必要なら権限を ON にする（マイク / カメラ / 位置情報 / 通知。デフォルトは全て OFF）
5. プッシュの **配信方式** を選ぶ（後述。デフォルトは「Pアプリカ経由」）
6. 「APK を生成」→「インストール」

## 特徴

- 生成はすべて端末の中で完結します（サーバーに URL を送りません）
- プッシュ対応版は GeckoView（Firefox 系）エンジンのテンプレートを内蔵し、サイトの Web Push を UnifiedPush 経由で受け取ります
- **Pアプリカ自身が UnifiedPush の配信機能を内蔵しているため、配信アプリ（ntfy など）を別途インストールする必要はありません。** ntfy などの配信アプリも引き続き使えます（「Pアプリカ経由」で、Pアプリカの配信が OFF の場合や Pアプリカが無い場合は、端末にある他の配信アプリが使われます）。配信手段が何も無い場合でも、生成したアプリは通常通りサイトを閲覧できますが、サイト側のプッシュ購読は失敗します
- Pアプリカの配信が動いている間は、常駐通知が 1 件だけ表示されます（プッシュの受信待機中であることを示すものです）。設定ページで配信を OFF にすることもでき、現在の配信状態（接続中かどうかや、登録されているアプリの数）も設定ページで確認できます
- 生成できるアプリの数には上限があります（生成アプリ 1 つが約 94MB と大きいためです）。デフォルトは **10 件** で、設定ページで 1〜100 件の範囲で変更できます。上限に達すると新しいアプリは作れなくなります（履歴を削除するか上限を上げてください）。上限を下げても、すでに作ったアプリや履歴が消えることはありません。既存アプリの「再生成」は上限に達していても行えます
- 外部認証（OAuth など）でも、認証フローがアプリの中で完結しログインできます（サイト側のポリシーで禁止されている場合を除く）
- 生成時に選んだ権限だけがアプリに入ります（OFF の権限は APK から取り除かれます）
- ファイルのアップロード、サイト内でのマイク / カメラ / 位置情報の利用に対応
- Pアプリカ本体の新バージョンは GitHub Releases でチェックできます（更新チェック先はアプリに組み込み済み。設定ページの「更新を確認」ボタン）
- 設定ページ（右上の「☰ 設定」）で、権限トグルのデフォルト値を決められます
- 生成されるアプリには、読み込み表示（スプラッシュ／プログレスバー）と、通信エラー時の再読み込み画面が付きます

### 配信方式（生成時に選べます）

プッシュの届け方は、アプリを生成するときに 2 つから選べます。
選んだ届け方は生成履歴に記録され、「複製」や「再生成」のときもそのまま引き継がれます。

- **Pアプリカ経由（推奨）**: プッシュの受信を Pアプリカがまとめて担当します。常駐通知は Pアプリカの 1 件だけで済みます。その代わり、Pアプリカがインストールされていて、配信が ON になっている必要があります
- **アプリ内蔵**: 生成したアプリ自身が配信機能を持ち、Pアプリカが無くても単体でプッシュを受け取れます。その代わり、生成アプリごとに常駐通知が 1 件ずつ表示され、接続もアプリごとに維持します

## 仕組み

- 内蔵の GeckoView テンプレート APK をベースに、URL・アプリ名・パッケージ名・アイコンを
  書き換えて再署名することで、サイトごとの独立アプリを生成します
  （バイナリ XML の文字列プール再構築による書き換え）
- UnifiedPush の配信は、Pアプリカ本体と生成アプリの双方に組み込める共有モジュール
  （`app.webgen.updist`）が担当します。配信プロトコルの仕様は
  [DISTRIBUTOR-CONTRACT.md](DISTRIBUTOR-CONTRACT.md) にまとめています
- 生成アプリの署名キーは初回起動時に端末内で作られ、端末内にのみ保存されます
- 署名キーはこのリポジトリには含まれていません

## 制限事項

- 生成されるアプリ 1 つあたりのサイズは **約 94MB** です（GeckoView エンジン一式を含むため、通常版の生成アプリより大幅に大きくなります）。Pアプリカ本体の APK も約 95MB です
- 生成履歴と、端末内で作られる署名キーは通常版とは別々になります。版をまたいで生成アプリを移す場合は、アンインストールしてから入れ直す必要があります（ログイン状態などのアプリ内データは引き継げません）
- ファイルのダウンロード（特に `blob:` 形式）は未対応です（通常版と同じ）
- サイトによっては、Firefox 系エンジン向けの表示や機能制限により、通常版と挙動が異なる場合があります
- 購読した直後は、プッシュの仕組み側で購読が有効になるまで数十秒ほどかかる場合があります。その間に送られたプッシュが届かないときは、少し待ってから試してください
- Pアプリカをアンインストールしたりデータを削除すると端末内の署名キーが失われ、以前に生成したアプリへ上書き更新できなくなります（再インストールが必要）

## ソースからビルドする場合

- 必要なもの: JDK 17、Android SDK (platform 34 / build-tools 34)、Kotlin コンパイラ
- `gecko-template/build_gecko_template.sh` で Gecko テンプレート APK を、
  `generator-push-app/build_generator_push.sh` で Pアプリカ本体をビルドします
  （Gradle デーモンを使わない手動パイプラインです）
- 署名キーとパスワードは各自で用意してください。パスワードは環境変数
  `WEB2APK_KS_PASS` で渡します（スクリプト内のデフォルト値はダミーです）
- 依存ライブラリ（GeckoView、UnifiedPush コネクタ、Tink など）の取得元は
  [gecko-template/DEPS.md](gecko-template/DEPS.md) を参照してください
- このリポジトリのスナップショットには、バイナリ素材（ランチャーアイコン PNG、
  `generator-push-app/libs/apksig-only.jar`、依存 AAR/jar、生成済み `template.apk`
  アセット）は含まれていません。これらはビルド時の成果物・依存物です
  （apksig は Android SDK の apksigner から抽出。ライセンスは
  `generator-push-app/libs/NOTICE-apksig.txt` を参照）
